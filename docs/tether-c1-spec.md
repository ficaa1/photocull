# Tethered capture in PhotoCull

Desktop product and implementation specification. The first release targets USB still capture with the Sony α7 III (ILCE-7M3) and α7C II (ILCE-7CM2). A photographer can light a test frame, adjust its RAW, switch to the next product folder, shoot from the body or computer, and see each new frame with the intended name, treatment and metadata. A reviewer can inspect an earlier frame throughout the shoot.

## 2. Start a shoot and choose a location

Open **Sources → Tethered camera → Start tethered session…** or run the palette action. The native dialog offers **Use open folder** and **Choose folder…**. Display the resolved capture path before enabling Capture. With no camera, the location, naming, adjustments and composition setup remain usable. Selecting a camera card in Sources continues to use the existing card workflow.

| Layout | Library root | Directory creation |
| --- | --- | --- |
| Single capture folder | Chosen directory | Write captures directly here until a shot is selected. |
| Session folders | Chosen directory plus `Capture` | Create `Capture`, `Selects`, `Output`, `Trash` as siblings beneath the chosen directory. Open only `Capture` as the recursive Library. The other three are conventional destinations. PhotoCull flags and soft Trash retain their existing behavior. |

**New shot…** accepts one validated component under the current capture location. Its dialog has a checked **Set as Capture Folder** box, allowing preparation of several shots in advance. A folder breadcrumb, **Subfolder** picker and **Set as Capture Folder** action also select an existing directory within the Library root. A switch takes effect for the next exposure accepted by the coordinator. All files from an already accepted exposure keep the original destination, even across a reconnect. Store the latest 12 successful relative locations per shoot and deduplicate on canonical identity. Creating a folder recursively is idempotent. Existing directories can be reused, existing files at any component are errors. Creating a partly successful layout reports the failing path and leaves valid directories available for retry.

Use an existing open session ID when its canonical folder and recursion scope cover the destination. A nonrecursive Library supports shooting directly in its root. Before enabling child shots there, offer **Include shot subfolders** with a one-time recursive open, carrying matching decisions by verified path/fingerprint from the nonrecursive session, including edits made under `writeSidecars:never`. Changing to a different Library root goes through normal open/flush, with explicit destination shown. Within the same recursive Library, switching shots makes no scan and never resets filters, selection or undo. Use ordinary local host folders, including approved writable external disks. Reject camera cards, registered card roots and their descendants as tether destinations. Honor the current card classification again after device changes.

Check root and destination identity before arming and publishing. Use canonical directory identities and parent-relative operations with no symlink/reparse traversal, including the final component. Reject absolute subfolder input, dot components, hidden task staging directories, control characters, reserved device names and trailing dots/spaces. A replaced or unmounted drive puts the shoot on hold. A matching path string on another volume cannot resume it.

Read usable bytes on the **destination volume** (available-to-user blocks or native equivalent) on selection, every two seconds while armed, and after publication or write failure. Show e.g. **186 GiB free · ≈2,300 shots**. Divide usable capacity after reservations and a 256 MiB safety margin by the median complete exposure size across the last 10 at the current model/host quality setting (RAW + JPEG combined). With no sample show bytes only. Before trigger reserve reported/estimated bytes for all pending objects (initial conservative budget 128 MiB per Sony still exposure). Block software release when free space is insufficient or unknown. Fresh checks at write time handle other writers. Keep already delivered data on disk, show a persistent destination error and allow retry.

## 3. Next Capture Naming and safe publication

Place **Name**, **Format**, token insertion and **Next filename** together. Initialize Name from the job folder basename and Format to `{Name}-{Counter:4}`. Example: for job `Ceramics`, shot `Blue` and counter 17, `{JobName}_{Subfolder}_{Counter:4}` previews `Ceramics_Blue_0017.ARW` and the paired `.JPG`. Editing Name does not rename a folder. Live preview updates on any relevant setting, physical control, counter or folder change. It is advisory and never consumes a number.

Extend the CommonJS/browser module `src/renderer/naming.js` with a capture-specific parser/formatter. Keep the existing `renderName(name,naming,index,{captured,now})` and `needsCapture` behavior for copy/export. Factor shared basename validation and padding. Existing lowercase tokens and their settings validators continue to mean exactly what they mean there. Use a separate token table for capture, case-sensitive, no nested braces, maximum template length 180. Show inline syntax errors and disable arming until corrected. Separators such as slash belong to the folder picker.

| Capture token | Value for a single logical exposure |
| --- | --- |
| `{Name}`, `{JobName}` | Aliases for the same editable job name (1–80 characters). |
| `{Counter}`, `{Counter:N}` | Decimal session counter, default minimum width 4. N is a single digit 1–6. Pad the magnitude, retain sign, never truncate overflow. |
| `{CameraCounter}` | Four-digit minimum, first value 0000. Key by locally hashed stable body identity across shoots, count once per distinct exposure regardless of template. It is independent of Sony shutter actuations and the card filename. If body identity is unavailable, show “Camera Counter unavailable” and require a different template before software release. |
| `{Date}`, `{Time}` | Camera capture wall date `YYYYMMDD` and time `HHmmss`, from the same timestamp. Fallback is host-local time at exposure acceptance (freeze timezone/offset). |
| `{ISO}`, `{Shutter}`, `{Aperture}`, `{FocalLength}` | Actual ISO digits, shutter rational formatted e.g. `1-125` or `2s`, f-number e.g. `f2.8`, focal length e.g. `85mm`. Use decimal point, trim redundant zeros, normalize exposure rational before formatting. |
| `{Camera}`, `{Subfolder}`, `{Original}` | Reported model, final destination leaf, original camera basename without extension. RAW and JPEG receive the same rendered stem. |

Use common capture metadata from the first complete object available for naming, prioritized as immutable per-shot header/EXIF, then exposure-time property snapshot. Never substitute a later dial reading. In preview use last confirmed choices, annotate **estimated** for metered values and **pending** for the undelivered original name. At publication a missing optional EXIF value becomes the literal `unknown` with a per-shot warning. A body release while naming is invalid still spools and shows **Needs name**. Allow repair before publish. Freeze the resolved stem on the first part. Keep the driver-validated original extension for each member. Normalize inserted metadata to NFC, replace unsafe separators/control characters with `-`, collapse runs, and validate the whole stem under existing 200-character filename limit and destination byte limit. Reject an invalid literal, empty/reserved result or unsupported extension. Never interpret camera-provided paths as host paths.

**Counter controls.** Store `next=1`, `resetTo=1`, `step=1`, with signed bounds ±999,999,999 for values and ±9999 for a nonzero step. Set Next edits the next value, Set start edits the reset target, +/− move forward/back by one configured step, Reset restores the reset target. Exhaustion blocks allocation with a corrective action. Changing shots retains counters. Serialize counter commands and exposure acceptance in one local transaction. Allocate the shot ordinal, both counters when available and the settings snapshot together. A failed shutter before any confirmed exposure consumes no counter. Once allocated, values survive failures, retries and restarts. Gaps are allowed. A duplicate camera notification or second object never advances either counter.

**No-overwrite protocol.** Rust downloads into a private `.photocull-tether` directory on the chosen destination volume. Per-member UUID filenames, create-new/no-follow handles, byte limit from declared length or free-space budget, streaming hash and fsync. Record intent before writing. Validate byte count, type signature and provider completion, close and sync before publication. Node reserves a common final stem in a durable ledger, checking the canonical directory for **all** same-stem RAWs, JPEGs and both XMP naming forms, including case/Unicode-equivalent variants. A collision chooses `stem-2`, `stem-3`, etc., independently of the capture counter. Serialize PhotoCull reservations per physical directory; a unique stem claim also spans concurrent PhotoCull instances sharing the destination (exclusive filesystem claim, held through pair settlement). Allocation checks reduce conflicts. They never authorize overwriting.

Publish each complete member atomically without replacement using descriptor-relative, platform-supported no-replace rename or same-volume create-hard-link then unlink owned staging entry, followed by directory sync where supported. The hard-link branch in `develop.rs:publish_export` provides a precedent. Its create-placeholder-then-replace fallback exposes an empty final entry and cannot serve this protocol. Use OS no-replace moves on filesystems without hard links (Linux RENAME_NOREPLACE, macOS RENAME_EXCL, Windows same-volume move without replace), subject to the destination probe. Never use a plain replacing rename or expose the destination while streaming. Test capability on folder setup with disposable entries. If neither primitive works, surface **Choose a capture volume that supports safe publication** before the shoot. When another writer wins the first final path, re-reserve a suffix and retry. If a late companion’s name is taken after its sibling is visible, preserve both existing files, keep the companion staged and offer **Save separately with unique name**. Never silently pair it with the foreign file. Persist the exception before the next normal scan: exclude that foreign member from any automatic pairing with this exposure across reopen. Extend the scan grouping inputs with these verified path/identity exclusions, so independent same-stem files keep their own decisions and XMP ownership warnings. No filesystem promises a two-file atomic rename. The journal records each member and recovers between them.

## 4. Event-driven Library ingestion

The unit of work is an **exposure**, with one or more **file objects**. Use a durable shoot UUID independent of the ephemeral `Library.scan` session UUID. Assign a strictly increasing `ordinal` at first positive exposure indication (or first object if that is the earliest signal). A software request awaiting confirmation has a separate request ID. The camera’s button and the native Capture button converge at this point. Persist identity before acknowledging acquisition.

| Record | Key fields |
| --- | --- |
| Shoot | `shootId, canonicalRoot, volumeId, folderId, recursive, activeRelDir, configRev, nextOrdinal, nextCounter, resetTo, step, lastExposureId` |
| Exposure | `exposureId, shootId, ordinal, stableCameraKey, providerShotKey?, requestId?, expectedHostRoles, targetRelDir, captureTime, captureCounter, cameraCounter?, frozenPolicy, stem?, status, currentItemId?` |
| Member | `memberId, exposureId, role, originalName, providerObjectKey?, declaredBytes?, receivedBytes, stageRelPath, sha256?, finalRelPath?, fileIdentity?, status` |
| Library delta | `{session,shootId,rev,exposureId,ordinal,upserts:[PublicItem],removedIds:[id],remap:[{from,to}],firstArrival,pairState}`. `PublicItem` extends the existing `publicSession` projection with `contentRev`, `exposureId` and `ordinal` for tether items. |

Adapter correlation order: provider exposure ID with object role, then an unambiguous body identity + storage identity + original folder/stem + camera sequence/capture time in the current transfer cohort. Persist immutable object identity or verified byte hash with exposure context to suppress re-delivery across reconnects. USB handles can recycle. Host time proximity, equal hashes alone, and “the last RAW seen” cannot establish a pair. Out-of-order bursts may interleave freely. If identity remains ambiguous, keep independently named items and report **Pair unconfirmed**. A declared RAW+JPEG camera setting may send only one type to PC. Derive expected host roles from save/transfer settings, refine from actual events. Treat a 3 s companion timeout as a status change to **Waiting for companion**, never as evidence for pairing. Allow a later proven mate after restart. Unsupported members such as HEIF remain recoverable in staging with a filename/type message.

On each published regular file, Rust notifies Node privately. `Library.ingestCapture` stats the final file, verifies containing directory and identities, and rebuilds only its affected directory/stem group with existing `groupFiles` semantics. Maintain indexes of member path and folded group key alongside `items`/`byId`, updating scan, ingest and forget together. Use numeric filename/path sort already used by scan. Never call `scan`, recursively enumerate the folder, or create a new session for an arrival. No general folder watcher is required. Existing photos at session start are indexed by the normal scan and never receive retroactive capture presets.

1. RAW first yields the normal path-hash RAW ID and immediate usable item. A later JPEG updates companion path, stat, fingerprint, size badges and content revision on that ID.
2. JPEG first yields a usable JPEG row as soon as published. RAW arrival replaces it atomically with the canonical RAW row (the existing 24-hex-character path hash). Emit one remap. Preserve decisions, `modified`, descriptive metadata, undo/redo batch IDs, queued sidecar state and the exposure’s frozen RAW settings. Apply RAW-only settings once. Never restore the initial rating over a click on the provisional JPEG. A JPEG-only host transfer stays a JPEG. A duplicate event is a no-op.
3. A partial pair owns one exposure, one ordinal and one chime. A second same-extension file or ambiguous multi-owner stem uses scan’s unpaired representation and a distinct reservation. A file already present with different identity is an external change. Never adopt it as a retry.
4. Serialize mutations for affected IDs with decisions, history, save, explicit XMP, grouping and forget. Support an in-session alias for an old provisional ID on user edits already in flight, resolve it **before** decision validation, and coalesce obsolete sidecar jobs. For operations requiring stable file sets (delete, export, copy or hand-off), snapshot the current owner set and hold a member lease or defer the operation on that exposure until settlement. Show why a pending pair is locked, with **Finish as single** after timeout. On deletion/tombstone, route a much later mate to recoverable unpaired ingest, never resurrect the deleted item.
5. Serialize the Library snapshot containing the new fingerprint and initial per-photo state, then send the delta. Acknowledge in the journal after save. Recovery replay reuses the exposure ID and existing decisions; it cannot apply the preset twice. Queue sidecars as part of the durable mutation, with actual disk writes after session save. Schedule thumbnail, visible preview, EXIF, AF/burst analysis in existing priorities and invalidate per-item preview/metadata/analysis state for remaps and changed fingerprints. Add `contentRev` to every image URL (including loupe, survey and prefetch) so immutable loopback cache entries cannot hide a newly delivered JPEG.
6. Renderer applies a delta by ID inside a single render pass, remapping `selected`, `marked`, `anchor`, pins, Compare panes, loupe requests and pending jump target. Preserve navigation context. If `rev` skips, fetch a current in-memory Library snapshot, rebuild indexes, retain matching selections and resume from its revision. New session IDs invalidate old subscriptions and in-flight render results.

## 5. Next Capture Adjustments and Metadata

A strip beneath Naming shows the selected adjustment source, six group checkboxes, metadata preset and initial decisions. Show a short source description such as **Copy from Primary · Blue_0017.ARW**. The primary is `state.selected` (active pane in Compare), independent of a multi-selection or pinned reference. Node resolves changes by Library ID. The renderer publishes primary changes and flushes Develop’s 300 ms pending save before acknowledging the source as ready. For body-triggered shots, publish each changed draft as a validated versioned source patch to the coordinator on change, coalescing unsent updates; indicate **Pending** until acknowledged. A body release uses the last acknowledged state. A UI shutter awaits the current draft/primary barrier. File or settings callbacks arriving later cannot change an accepted exposure.

| Mode | Lookup at exposure acceptance | Result |
| --- | --- | --- |
| Default | `settings.defaultRecipe` → `RecipeStore.get` → `neutral` | Freeze that recipe’s partial patch. Native `base_settings(info)` derives as-shot WB, disabled sharpening/NR and enabled lens profile for the incoming RAW. |
| Copy from Last (initial mode) | Latest previous accepted exposure of this shoot with a RAW or expected RAW, by ordinal. Prefer its current acknowledged per-photo edits. During a burst use its frozen patch while its RAW is still in flight. | First exposure falls back to Default with a visible source label. Out-of-order transfers cannot turn an older exposure into Last. |
| Copy from Primary | Current open session and eligible non-trashed RAW. Resolve the underlying RAW adjustments even when viewing an edited hand-off. | If no eligible source, show **Default · no primary RAW**. An explicitly chosen different primary applies on the next shot. |
| Specific Recipe/Style | Saved or built-in recipe ID from `recipes`. Show the selected recipe name. | Freeze the recipe content. If removed before another capture, report **Recipe missing** and show the Default fallback. Renaming a preset leaves ID references valid. |

**Adjustment clipboard.** Persist a selection of field groups. The existing Develop Copy/Paste clipboard remains available for manual edits. Source settings are `item.develop.settings ?? recipe.settings`, the same resolution as `develop-get`, with the configured default/Neutral fallback. These are partial settings over the incoming photo’s native base. Never copy a calibrated per-source `develop_info.base` or the donor’s resolved camera WB or lens profile data.

| Group key and label | Paths in the pinned Lightcraft DevelopSettings schema |
| --- | --- |
| `wb` · White Balance | `wb`. Retain `mode`. In `asShot` omit donor temperature/tint; `custom` carries Kelvin temperature and tint. |
| `light` · Exposure/Light | `light` (exposure, contrast, highlights, shadows, whites, blacks), `hdr` if present. |
| `curve` · Tone/Curve | `curve`, including the channel point arrays and parametric controls. |
| `detailColor` · Detail/Color | `profile, treatment, detail, color, mixer, point_colors, bw_mix, grading, calibration, effects, vignette, grain`. `profile.id` supports the existing Neutral and Color looks. |
| `optics` · Lens Corrections | `optics` including `lens_profile`, correction strengths, CA and vignetting. The target RAW supplies the actual lens/embedded data. Lensfun remains an attributed, opt-in download. |
| `orientation` · Orientation/Rotation | `orientation` and `geometry.rotate` (relative adjustments on the oriented source). Right-angle values serialize using Lightcraft’s enum, e.g. `Rotate90`. Display guides, aspect mattes and overlay offsets are independent. |

Default takes its whole recipe without a mask. Specific Recipe with **Use entire recipe** (initial setting) also takes the complete checked recipe, including fields outside the six groups. Choosing **Select adjustments** in Specific, or a copy mode, starts from a clone of the default recipe patch. For each checked group, remove its destination paths and insert only paths present in the source. This makes a donor at native defaults reset that group to the incoming RAW base. Unchecked groups retain the configured default. Replace arrays wholesale. For selective copying, preserve the destination process/version, keep spatial masks, spots, crop and perspective tied to the destination, and copy section enable/disable entries only for transferred sections. Reject unsafe keys and invalid shapes using `checkSettings` plus native typed deserialization. Record recipe ID for provenance and the materialized partial patch in `develop.settings` (including `{}`). A later recipe edit or removal cannot alter the photo’s rendered appearance. Never copy `tiff`, `handoffs`, `editedBy`, missing/exported flags or revision stamps. [Lightcraft settings at PhotoCull’s pinned revision](https://github.com/storytold/lightcraft/blob/d58b4d67238ef1aafd8e3394a9f8428a3d91e561/crates/develop/src/settings.rs)

**Applying the treatment.** Initialize per-photo `developState`, metadata and decisions in the same Library mutation. Use `Library.developSet`’s validation/state rules internally without independent saves for each field. A provisional JPEG can carry a pending RAW patch in the journal. A standalone JPEG keeps its metadata and decisions, with no RAW Develop badge. For optional **Show developed preview in Review**, resolve the frozen settings and call existing `develop_render(session,id,settings,settled)` through the bridge. Show a quick camera preview, replace it with the 1600 px draft or 2560 px settled color-managed frame as requested. Develop uses the existing render queue, panel and controls. Native renders share a bounded foreground queue across both surfaces (one active plus latest pending display request). Key caches by session, ID, source fingerprint, settings digest, render size and original/edited state. A late result cannot replace a new selection or manual edit. Retain a camera preview plus **Develop preview failed · Retry** on failure. The existing Show original action bypasses the treatment in Review. On a saved hand-off the existing external-edit view still takes precedence. Previewing does not produce a TIFF.

**Metadata.** Choose **None** or an existing `SettingsStore.snapshot().presets` ID. Snapshot its creator, copyright, caption and keywords for each exposure; ignore the preset’s copy naming and folder rules here. Optional initial decisions are `rating:null|0..5`, `color:null|""|"1".."8"` and `pick:null|true|false`. Null leaves existing/imported state intact, empty color explicitly clears, false clears an initial pick. With no earlier state the defaults are `none,0,null`. Choices are visible in the filmstrip, filters and Details immediately. A capture preset never changes the global active preset. Reuse metadata limits (creator/copyright 1024, caption 8192, at most 100 unique keywords of 128 characters). If a referenced preset disappears before acceptance, label **Metadata preset missing**, omit its text fields and retain explicit initial decisions. Never substitute a different customer’s metadata.

Extend session decisions with an optional per-item `captureMetadata:{creator,copyright,caption,keywords,presetId}` and capture identity/revision. An enabled preset freezes even its blank fields. With None, latch empty descriptive overrides so turning on a different global preset later cannot tag an earlier shoot through a delayed autosave. In Details, overlay nonempty snapshot fields on camera/imported values and merge keywords, preserving order and removing duplicates. Write `dc:creator` (Seq), `dc:rights` and `dc:description` (Alt, x-default), `dc:subject` (Bag). Use existing `photocull` flags, rating/label mappings, configurable eight label IDs and `xmp:Rating/Label` rules. Pick is a PhotoCull decision. Preserve other XMP namespaces and existing values for blank fields. Read these descriptive fields on session/XMP restoration, observe current newer-XMP precedence, and include captures with metadata-only changes in explicit source-XMP export and unsynced recovery. Store the selected treatment through the existing portable `photocull:develop` representation.

`shouldWriteSidecars(settings,session.removable)` gates **each autosave**: `except-cards` by default, `always` or `never`. Decisions, adjustments and metadata survive reopening with XMP off. Explicit **Write source XMP** follows existing separate policy. Prefer the newest valid existing sidecar per Library rules and preserve path/source ownership checks. A shared-stem conflict warns and retains the local copy. Never embed into a camera object, captured RAW, or original JPEG. For copy/XMP and finished export, thread the per-item descriptive overlay through `transfer.cjs`, `metadata-writer.cjs` and native `export_metadata`, then apply explicit output overrides and the existing export metadata policy last. Photos without the new snapshot retain their existing preset behavior. A later explicit edit to a captured photo wins over its frozen defaults.

## 6. Camera panel and native adapter

Capture One lists tethering and Live View for **α7 III** from 11.1.0 and **α7C II** from 16.3.2. Its matrix lists wireless for α7C II only of these two. This specification uses USB for both. Sony’s current Remote SDK model list includes ILCE-7CM2 and omits ILCE-7M3. The proposed common adapter uses libgphoto2’s PTP2 Sony **Control** profiles, which mark both models capture/preview capable. A profile entry is evidence for a transport choice; individual operations still need descriptor probes and hardware verification. [Capture One camera table](https://support.captureone.com/hc/en-us/articles/360002718118) · [Sony SDK compatibility](https://support.d-imaging.sony.co.jp/app/sdk/en/index.html) · [libgphoto2 control profiles](https://github.com/gphoto/libgphoto2/blob/6d5c61ef7687b74fe792e4aeae7fc40f2ad42d88/camlibs/ptp2/library.c)

Implement a blocking camera actor per connected body, with one active body in the workspace. `discover, open, describe, set, trigger, halfPress, focusStep, waitEvent, downloadTo, previewJpeg, close` form the adapter boundary. Use libgphoto2 abilities/port discovery, `gp_camera_get_config` widgets for types, allowed values and read-only flags, single-widget writes and readback, `gp_camera_trigger_capture` or supported capture-return-path mode, `gp_camera_wait_for_event` for body shots/file additions and `gp_camera_file_get` to an owned file sink. Deduplicate a file returned by both capture and a later event. `gp_camera_capture_preview` supplies JPEG bytes when supported. Normalize vendor action widgets through a reviewed per-provider key/type map. Never expose free-form widget paths or permit arbitrary PTP commands from the renderer. No card deletion, formatting or clock setting. Prioritize release of held controls, transfer and camera events over viewfinder polls. Keep long native I/O off the UI and sidecar event loops.

Package and pin the supported adapter/runtime per native target; record exact library, libusb, camlib and driver versions in the offline inventory, including redistributable license texts. Validate access on macOS and Linux without competing camera owners. On Windows qualify the shipped adapter against the actual USB driver for each body on a clean machine. If it cannot open the normal driver, show **Transport unavailable on this system** and qualify an alternate native provider independently before advertising support. Never silently replace a user’s USB driver. Absence of the camera runtime disables only tethering.

**Connection header.** Show explicit selection if multiple cameras are found; display model, firmware or “unknown”, USB transport/status, reported battery (percent, discrete icon/level or unavailable), save destination and **Reconnect / Disconnect**. Do not turn coarse battery bars into an invented percent. **Capture** is the large primary inside this panel, **AF-On** is a momentary control, **Live View** and **Pause tether** are separate toggles. Disable capture until a writable shoot is armed, the provider accepts release, the queue has capacity and physical camera state permits a shot. Software shutter repeats require discrete clicks/keypresses. Bursts come from the camera drive. Always release half-press on pointer/key up, focus loss, pointer cancel, disconnect, pause or timeout; provide a bounded pulse for devices exposing only an AF command.

Each property is `{key,label,kind,value,display,access,choices?,range?,reason?,propRev}`. ## 7. Viewer follow, stage and reference

**Follow new captures** stores `immediately|whenReady|off`. **Pause following** temporarily suspends an enabled mode and remembers it. **Pause tether** blocks new software shutter commands and suspends live frames; continue draining already announced objects and any incoming physical shots. A camera may still fire from its hardware shutter. Display **Paused · body captures still received** when appropriate.

| Viewer state | Visible result on arrival |
| --- | --- |
| Immediately | In Review/Develop move only after the first displayable frame decodes (thumbnail, embedded/companion preview or develop draft). Keep it visible until the requested better rendition has decoded. |
| When Ready (default) | Keep the previous photo visible until a `preview` image for fit/Review has decoded or the settled adjusted frame is displayable when live development is active. At native zoom explicitly request `full` for the camera rendition. Readiness means the chosen surface has decoded its final requested preview, independent of the thumbnail or disk-write notification. |
| Off / Pause | Insert/update filmstrip and counts silently. Keep current photo, zoom, scroll, focus, selection and editor draft. **Pin Reference Shot** pins the active non-trashed session photo as the left pane of `survey.js`. ## 8. Live View and composition

Use a stage inside the existing `main` webview, with **Dock / Expand / Close Live View**. Stage occupies the center viewer while keeping the camera panel and filmstrip available. Dock embeds the same canvas in the tether panel so Review can remain visible. Moving between them reuses the subscription. Closing the last consumer, losing the session or pausing tether stops polling and releases camera Live View. A camera that suspends live feed during exposure keeps the last frame with **Capturing…**, then resumes when its adapter reports ready.

**Binary transport.** The actor retains just the newest camera JPEG, with monotonic frame sequence, timestamp, decoded dimensions and orientation. The bridge issues one outstanding `tether_live_frame` long-poll at a time. Rust returns `tauri::ipc::Response` with the existing Develop envelope: little-endian u32 header byte length, UTF-8 JSON, JPEG bytes. Header is `{v:1,streamId,epoch,seq,cameraMonoMs,width,height,orientation,jpegBytes}`. Validate header ≤4 KiB, JPEG ≤8 MiB, raster ≤24 MP and payload length exactly; reject a malformed or stale frame. A 500 ms poll timeout returns a header with unchanged sequence and zero bytes. A stopped stream returns `STREAM_CLOSED`. No JSON byte arrays, base64, Node stdio or per-frame Tauri events. One decode in flight using `createImageBitmap` or `Image.decode()` and a bounded fallback Blob URL, paint at animation frame, close/revoke superseded images. Poll up to 30 fps, targeting 15–30 displayed fps if the camera delivers it. Count skipped source sequence numbers. A slow viewer must drop live frames before it delays a photo transfer.

**Focus tools.** The live loupe uses `ImageView`’s normalized center and DPR-aware Fit/100% geometry. Drag or use accessible pan controls to position the 1:1 region, with reset to center. 100% means one **delivered preview pixel** per device pixel. Offer separately labeled camera magnification only if the adapter supplies an actual magnified stream and pan facility. AF-On uses the same half-press or bounded AF pulse as the camera panel. Near 3/2/1, AF, Far 1/2/3 call capability-checked commands. A single click performs one step. On hold, repeat after 350 ms, at most 6/s with one outstanding, stopping at pointer up, focus loss, error or capability change.

**Shared coordinates.** `overlays.js` receives the oriented source rectangle, content crop, zoom/pan transform, DPR, analysis bitmap and layer settings. Use one mapping from normalized oriented image space to device pixels: sensor/display orientation first, crop/fit next, then the pane’s zoom/pan. Raw-derived rotated/cropped develop frames already encode that transform. Tag each source with its coordinate space and apply rotation exactly once. Letterbox bars never participate in analysis or guides. ResizeObserver and each `ImageView` change redraw the layers; replace source and transform in one frame. Overlays default to pointer-transparent and excluded from keyboard focus. A specific **Move overlay** tool captures drags and arrow nudges while active, then returns control to the image.

| Layer/tool | Rendering and controls |
| --- | --- |
| Grid & guides | Off, Rule of Thirds at 1/3 and 2/3, Golden Ratio at 0.382 and 0.618, Golden Spiral, Center Crosshair or Custom (1–128 rows/cols, interior lines at i/N). For the spiral fit a golden rectangle centered in the reference box, tile successive squares reduced by φ, connect their tangent quarter circles, stop below one device pixel; allow mirror/clockwise flips. ## 9. Connection, transfer and recovery

| Machine | Transitions and ownership |
| --- | --- |
| Camera (Rust) | `offline → discovering → connecting → ready` on successful probe. `ready ↔ paused` from operator action. `ready/paused → lost → reconnecting → ready/paused` on the same verified body; increment the connection epoch and re-enumerate capabilities. Manual Disconnect → `draining → offline` and cancels automatic reconnect. Wrong body → **Choose camera**. Unsupported transport, access denied or another owner → actionable error with Retry. |
| Shutter (Rust + coordinator) | `requested → dispatching → confirmed \| failed \| outcomeUnknown`. A repeated request UUID retrieves the same receipt. If the link dies after dispatch, never resend automatically. Reconcile by camera events and committed objects. A successful trigger response is acceptance by the camera; the save acknowledgment follows durable file publication and Library save. |
| Member | `announced → receiving → staged → reserved → published → ingested`; `held` stores retryable failure, preceding state and reason. Write each transition needed to redo a filesystem side effect before starting it. Partial members are hidden. Preserve completed members if a sibling fails. |
| Exposure | `accepted → transferring → availablePartial → complete` or `needsAttention`. A single complete host object can go directly to complete. Complete requires all expected host roles, or adapter end-of-exposure with confirmed single role, or explicit Finish as single. First Library upsert marks first arrival. Track transfer state separately from viewer decode state. |
| Live View | `off → starting → streaming ↔ suspended → stopping → off`. Device loss closes the stream and invalidates epoch. Auto-restart on same body only when the operator had Live View on, tether is resumed and a visible consumer still exists. |

Reconnect on device-added notification or back off 1, 2, 4, 8, 16, then 30 s between attempts until manual stop. Preserve folder, step, next number, overlays, pins, pending members and policy snapshots. Re-identify by stable body identity, not USB port; if identity is unavailable require an explicit choice. Re-probe host delivery mode, card readiness and destination identity before rearming. Never replay exposure or setting commands on reconnect. Fetch available pending objects only when their identity is verifiable. Clearly label a disconnected PC-only transfer **Recovery unconfirmed**; some cameras discard volatile buffers.

**Missed shots on the card.** A photo the camera saved to its card but never delivered (a cable pulled mid-burst, a Wi-Fi drop) can be copied from the card. **Pull missed shots from card** in the camera panel, or the automatic pass a few seconds after a reconnect within the same shoot (`autoBackfill`, on by default), lists the card with GetStorageIDs, GetObjectHandles and GetObjectInfo and reads files with GetObject only; nothing on the card is deleted or changed. Only RAW and JPEG photos taken since this shoot session started count, measured on the camera's clock using the offset its tethered shots showed (one minute of slack, five without any shot yet), or since the newest capture time a complete earlier pass settled. Files with the same capture second and stem form one exposure. A file is already here when a member of that capture second and role has the same stem or size; a member whose transfer never completed (`CAMERA_LOST`, `INCOMPLETE`, `IO_ERROR` or `NO_SPACE` before any staged bytes) is reopened and receives the card file, and an exposure missing an expected role gains it. Other files become new exposures with the active location, naming, counters, adjustments and metadata, keyed by body, capture time and stem so another pass finds them. Each file is staged, hashed, journaled and published exactly like a live capture. Card reads yield to live captures: they run one file at a time only while no shutter, camera object or receive is pending, and Pause and Cancel take effect between exposures, never inside a RAW+JPEG pair. Composition Mode test shots of this launch are never pulled. Sony PC Remote connections often hide the card or refuse the storage operations; that is reported as a plain note and the session stays connected.

**Durability and recovery.** Node owns one versioned `dataDir/tether/ledger.sqlite` (bundled Node 24 `node:sqlite`, full sync, local disk, transactions). Tables: `shoots`, `camera_counters`, `exposures`, `members`, `requests` and `claims`. Require unique `(shootId,ordinal)`, `requestId`, `(exposureId,memberId)`, verified provider notification key within its identity domain, and `(volumeId,directoryId,foldedStem)` while reserved. Jobs reference app-generated IDs. Store frozen config at acceptance; stage paths, expected size and hashes have journaled ownership. Rust receives write plans only through its private Node calls. A caller cannot manufacture one by supplying a path.

On reopening, reconcile pending records against the recorded volume, directory identity, owned staging files and final paths. An exposure ID in the durable Library snapshot is the idempotency marker across the two stores. For JPEG-first recovery when RAW publication interrupted a save, load the provisional JPEG decision by its journaled path hash, verify its saved size/mtime against the published member, and migrate it before applying any initial defaults. Prefer a newer valid user edit or sidecar using the existing tie rules. If the final file matches staged identity/hash, continue at published/ingest. If the stage matches, retry publishing. If both names refer to the verified same inode, cleanup only the owned stage. If identity differs, hold for a fresh unique destination. Resume partial byte ranges only with provider support and verified object identity/length; otherwise stream a fresh stage file. If a journaled file is absent, report missing and offer redownload if available. Only clean stale claims after proving their owner is inactive and reconciling all pending members. Never remove unknown files from staging or the camera. After a crash, restore capture-associated per-photo state before ordinary scan fingerprint mismatch handling can discard JPEG-first edits. Normal reopens can scan once; camera reconnect and event-gap recovery use the in-memory session plus the journal.

Start/stop, normal folder open, device auto-open, backup, copy, settings import and destructive file operations share the existing backend busy checks. Suppress card auto-open while tethered. Block root replacement and settings import until the actor stops accepting triggers, drains recoverable transfers and flushes Library/XMP. Offer **Stay here** or **Stop tether and open folder**; a surprise unplug never forces a session change. Allow routine Review/Develop edits during transfer. On close, drain or persist resumable work, release held camera controls and close the handle. If data only exists on the camera, explain the pending transfer before intentional disconnect.

**Status.** Show queued objects, active transfers, pending companions, bytes received/total if known, and camera buffer occupancy only if actually reported. Count waiting exposure objects separately from native camera buffer slots. Measure transfer MB/s as bytes received / 1,000,000 / monotonic transfer seconds (rolling 2 s for live readout). Report trigger-to-first-byte, transfer duration, published-to-usable preview and trigger-to-visible in ms, using monotonic clocks within each process. For cross-process end-to-end numbers timestamp start/end in the shell using a renderer “presented” acknowledgment, or calibrate clocks; omit unavailable stages for body shutter. Throttle progress to 4 Hz, status announcements to meaningful transitions. Use a bounded queue (32 outstanding host objects, 2 receiving, 1 per handle when required), with disk-backed overflow announcements so incoming stills are never dropped as live frames can be. Apply backpressure to software capture, reduce live polling and show **Camera busy** on provider saturation. If the body outruns storage, count/report unconfirmed or lost objects where known. A short optional Web Audio chime once per newly visible-to-Library exposure follows audio unlock by user gesture; reconnect/replay, upgrades, silent mode and repeat notifications do not chime.

**No camera detected.** Provide model-specific steps: power/wake the camera, select still shooting, attach a data-capable USB cable directly, exit playback and close competing tether apps. α7 III: USB Connection → PC Remote, set Still Img. Save Dest. and RAW+J PC Save Img before connecting. α7C II: USB Type-C → Remote Shoot (PC Remote), then check Remote Shoot Setting, host type and size. PC+Camera requires writable media. Show last attempt, Retry and copyable diagnostics containing model, transport, driver version and sanitized error codes. Keep customer filenames, serial numbers and loopback credentials out of diagnostics. [Sony α7 III guide](https://helpguide.sony.net/ilc/1720/v1/en/index.html) · [Sony α7C II connection](https://helpguide.sony.net/ilc/2360/v1/en/contents/0903_pc_remote_function.html)

| `tether_live` | `{shootId,epoch,enabled}` | `{streamId:null\|id,state}`. Start/stop the feed, release outstanding polls on stop. |
| `tether_live_frame` | `{shootId,epoch,streamId,afterSeq}` | Binary envelope in section 8; one waiter per stage. |
| `tether_review_frame` | `{session,id,kind:"preview"\|"full",original,contentRev}` | Same binary envelope pattern, header `{v:1,id,contentRev,width,height,jpegBytes}`. Shell loads existing authenticated loopback photo bytes for validated Library ID, bounded to 64 MiB. Reuse decoded display blobs when already available; for analysis above limits request preview size. |
| `tether_overlay_pick` | `{shootId,source:"file"\|"session",session?,id?}` | Native file picker or session snapshot; pure inert raster stored under app data. Return `{assetId,width,height}` or null on cancel. For a developed session photo, use its current settled native frame; for other types use the preview resolver. |
| `tether_overlay_image` | `{shootId,assetId}` | Binary PNG (preserves alpha), bounded/re-encoded, from a registered asset belonging to this shoot. |
| `tether_recover` | `{shootId,exposureId,memberId?,op:"retry"\|"finishSingle"\|"saveSeparate"\|"repairName",name?}` | `{exposureId,state,issue?}`. Validate basename for repair and use the normal exclusive publish path. A retry reuses IDs/counters. |
| `tether_presented` | `{shootId,exposureId,ordinal,quality:"quick"\|"settled"}` | Null. Ignore duplicates, stale sessions and impossible ordinals; record display latency only. |

Use stable error codes `STALE_SESSION, STALE_REV, CAMERA_LOST, CAMERA_BUSY, CONTROL_LOCKED, UNSUPPORTED, NO_SPACE, DEST_CHANGED, NAME_INVALID, NAME_TAKEN, INCOMPLETE, STREAM_CLOSED, IO_ERROR, INVALID_FORMAT`. `INVALID_FORMAT` marks a staged file whose bytes are not the image its name promises; it stays in staging and is never retried or published. Include a readable recovery action. For example a stale ISO write returns `STALE_REV` and the latest revision; refresh descriptors without resubmitting the requested ISO.

### Rust-to-Node private methods and events

These methods are **stdio-only**, registered only in native desktop sidecar mode and excluded from `RENDERER_METHODS`. One serialized transaction per shoot handles intent, allocation and reconciliation. Stage receipts do not transfer image data through stdio.

| Private method | Arguments → result |
| --- | --- |
| `tether-bind` | `[validatedRoot,rootIdentity,layout,includeShots,existingSession?] → {shootId,session,configRev,libraryRev,recoveries}`. Create/reopen ledger and bind to Library. |
| `tether-set-location` | `[shootId,expectedRev,verifiedRelativeDir,directoryIdentity,activate] → {configRev,location}`. Rust has already checked/created the folder. |
| `tether-request` | `[shootId,requestId,primarySeq,op,result?] → {state,dispatchAllowed}`. Unique create/dispatch/resolve transitions; commit frozen software-trigger intent before dispatch, reuse it for its first confirmed exposure. Additional burst frames freeze at their own acceptance. |
| `tether-accept` | `[shootId,epoch,requestId?,providerExposure,hostRoles,cameraSnapshot] → {exposureId,ordinal,counters,targetDirIdentity}`. Dedupe or allocate. Physical triggers freeze policy here. |
| `tether-member` | `[shootId,exposureId,objectDescriptor] → {memberId,stageRelPath,status}`. Journal only validated source object data and the UUID stage intent before download. |
| `tether-reserve` | `[shootId,memberId,stagedReceipt,shotMetadata] → {stem,finalRelPath,claimId}`. Verify receipt, materialize the naming context, atomically reserve (or return existing plan). Rust acquires the same-volume stem claim before publication; on claim conflict return to allocation with occupied suffix excluded. |
| `tether-ingest` | `[shootId,memberId,claimId,publishedReceipt] → {exposureId,itemId,rev}`. Idempotent Library transaction with validated path/identity, replay-safe delta. |
| `tether-journal` | `[shootId,op,detail]`. `issue` records member/exposure failure and prior stage, `conflict` invalidates an unused reservation, `recovery` enumerates or transitions only that shoot’s owned records, `close` flushes/unbinds. Return `{state,pending,records?}`. |
| `tether-backfill` | `[shootId,op,detail]`. `window → {since}` earliest camera time to scan; `plan` takes `{body,hostRoles,objects:[{handle,storageId,name,role,bytes,captureTime}]}` and returns `{groups:[{captureTime,objects}],present}`; `prepare` re-checks one exposure's objects and returns `{exposureId,members:[{handle,storageId,memberId,stageRelPath,status,originalName,declaredBytes}]}` after accepting or reopening; `synced {through}` records a complete pass. |
| `tether-session-frame` | `[session,id,kind,original,contentRev] → {contentRev,width,height,route}`. Resolve bounded, authenticated `/image/<session>/<id>/<kind>` or scoped cached display result for Rust only. Never accept a caller URL for native fetching. |
| `tether-asset` | `[shootId,op,asset]`. `bind` records hash, raster size and local cache ID after native import; `lookup` verifies ownership; `clear` releases the binding. Return validated asset descriptor or null. |

Node emits Library mutations through existing `send(event,payload)` → `backend.rs` → Tauri. Rust emits connection/frame-state/telemetry events to `main`. Add these names to `bridge.js:EVENTS` and expose unsubscribe functions. Every event carries `v:1,shootId`; Node state also includes `session`; camera events include `epoch`. Keep independent increasing revisions per state domain. On initial subscription fetch current snapshots **after** listeners are installed, then apply subsequent newer events.

| Event | Additional payload |
| --- | --- |
| `tether-connection` | `{epoch,state,device,actions,properties,propRev,reason?}`. Full initial/reconnected snapshot. |
| `tether-properties` | `{epoch,propRev,changed:[descriptor],removed:[key],actions?}`. Gap → `tether_devices` then idempotent `tether_connect` for snapshot. |
| `tether-config-changed` | `{session,configRev,location,counters,config}` including effects of a counter reservation. |
| `tether-transfer` | `{epoch,seq,exposureId?,memberId?,phase,bytes,total?,queued,receiving,pendingPairs,buffer?,mbps?,latency?,freeBytes?,estimatedShots?}`. Coalesce; counts are gauges. |
| `tether-library-delta` | `{session,...LibraryDelta}` from section 4. Keep rev contiguous across ingests and remaps; separate from transfer seq. |
| `tether-live-state` | `{epoch,streamId,state,reason?,deliveredFps?,dropped?}`. Frame pixels travel only through binary IPC. |
| `tether-issue` | `{session,exposureId?,memberId?,code,message,retryable,actions[]}`. Deduplicate by owner/code until resolved. Existing XMP errors still use `sidecar-warning`. |
| `tether-backfill` | `{epoch,state:"scanning"\|"pulling"\|"paused"\|"cancelling"\|"done"\|"cancelled"\|"interrupted"\|"unavailable"\|"error",storageAvailable,auto?,paused?,scanned?,listed?,current?,total?,shots?,pulled?,failed?,present?,already?,message?}`. `current` and `total` count exposures. |

Example trace for a body-fired RAW+JPEG: actor receives JPEG added → `accept` assigns ordinal 17 → `member` → private staging → `reserve` → exclusive publish → `ingest` → Library delta inserts JPEG. Photographer rates it 4. RAW arrives with same provider shot key → same exposure → second member, same stem and counters → publish → `ingest` remaps to RAW with rating 4, pairing and recipe → renderer swaps underlying image without moving the current view. A reconnect repeating either file returns its existing receipt.

## 11. Settings, actions and validation

Add a normalized `tether` block to the existing version-1 settings file under `SettingsStore.folder`. Defaults for an old installation are below; perform a nested merge on update and validate bounds and finite numbers on both settings patch and import. Selective modes consume `groups`; entire-style selection is a boolean independent of mode.

~~~json
{
  "tether": {
    "version": 1,
    "layout": "single",
    "namingTemplate": "{Name}-{Counter:4}",
    "counterStart": 1,
    "counterStep": 1,
    "adjustments": {
      "mode": "last",
      "recipeId": null,
      "entireRecipe": true,
      "groups": ["wb", "light", "curve", "detailColor", "optics", "orientation"]
    },
    "metadataPresetId": null,
    "initial": {"rating": null, "color": null, "pick": null},
    "follow": {"mode": "whenReady", "pauseOnInspect": true, "developedReview": false},
    "chime": false,
    "autoReconnect": true,
    "autoBackfill": true,
    "composition": {
      "grid": {"shown": false, "type": "thirds", "rows": 3, "cols": 3, "color": "#ffffff", "opacity": 0.5, "mirror": false, "clockwise": true, "guides": []},
      "aspect": {"shown": false, "ratio": "2:3", "orientation": "portrait", "matte": 0.65},
      "overlay": {"shown": false, "opacity": 0.5, "scale": 1, "x": 0, "y": 0, "followCrop": true},
      "mask": {"shown": false, "color": "#00ff00", "opacity": 0.55, "threshold": 0.03},
      "peaking": {"shown": false, "color": "#ffff00", "sensitivity": 0.5},
      "warning": {"shown": false, "high": 250, "low": 5, "shadows": false},
      "histogram": {"shown": false, "mode": "rgb+luma"}
    }
  }
}
~~~

`layout=single|session`, `adjustments.mode=default|last|primary|recipe`. Require valid bounded recipe/preset IDs or null and unique allowed group keys. Grid type `thirds|goldenRatio|goldenSpiral|crosshair|custom`, guide list at most 64 `{axis:"x"|"y",at:0..1}`; color is `#RRGGBB`, unit opacities/sensitivity 0–1, scale 0.1–4. Histogram modes `rgb|luma|rgb+luma`. Naming bounds appear in section 3 and composition bounds in section 8. Unknown future tether schema versions leave the saved section intact and disable tether setup until compatible; normal culling settings still load. At Start, clone these defaults into shoot config plus `jobName`. The panel edits the current shoot; Settings → Tether edits defaults for subsequent shoots. Read runtime chime/reconnect preferences from current Settings. Persist per-shoot config, counter progress, recent destinations, local overlay asset and pinned relative file identity in the ledger. Verify pinned file fingerprint and root on reopening. A missing asset disables Show with a Choose file action. Explicit camera disconnect, temporary viewer pause, active holds/streams and live preview pixels are transient. Settings bundles include portable defaults/shortcuts and resolve bundled recipe/preset IDs using the bundle importer. Exclude journals, serials, counters, pins, paths and customer artwork from the bundle.

**UI placement.** Tether is a Sources entry and an inspector panel, accessible with the camera offline. Retain Grid, Review and Develop IDs/modes. Opening Live View stage sets a stage-specific command context. Closing it restores the previous mode and focus. Use the 248 px Details width, collapsible Develop-style sections, 24–28 px controls, tabular figures and 24 px minimum targets. Shutter uses `.button.primary` / `--ivory` within Camera; active toggles use `--accent`, background `--panel`/`--canvas`, transient pills `--overlay` and warnings `--warn`. Keep app bar’s Export action. At narrow widths reuse the inspector overlay and collapse camera details before hiding shutter/connection state. Give disabled controls persistent reason text via `aria-describedby`, visible focus and polite status announcements. All frequent actions have buttons, palette entries and Help/Keyboard entries. Use existing settings Save/Cancel and native-dialog focus restoration. [Interface conventions](ui.md) · [Current workflows](workflow.md)

| --- | --- | --- |
| `tether-shutter` | **T** | Grid, Review, Develop, Compare or stage; only when tether is armed and ready. Ignore key repeat. |

### Acceptance criteria

Use synthetic, offline fixtures and temporary app data. Drive the normal public bridge, real Library/store and native adapter interface with a deterministic test double. Extend the existing behavior owner when one exists. The following are release criteria, not measurements of this proposal.

| Exercise | Observable pass condition |
| --- | --- |
| Folder + burst | Start on an empty root, make Blue and Red shots, change destination while two captures are in flight. Each pair lands at its acceptance-time target. Existing Library ID, edits and references survive. Count zero full scans from first arm through reconnect and shot switches. |
| Pair permutations | RAW only, JPEG only, JPEG→RAW with user edit, RAW→JPEG, interleaved bursts with identical original stems in different folders, late and duplicate events. Exactly one item per proven pair, independent rows for ambiguous objects, correct badges on reopen and undo still owns the right item. |
| Naming + crash | Validate every token/width, mixed date/time zone, unsupported camera counter, negative step, Windows reserved names and old copy presets. Race two writers against a pre-existing RAW/JPEG/XMP. Kill the process after reservation, stage sync, first publish and Library save. Existing files retain hashes, retries consume no new numbers, every recoverable member is visible or accounted for. |
| Adjustments + XMP | Light −0.7 EV, custom WB and crop on donor; carry only WB, verify new RAW has the default exposure and its own geometry. Repeat with as-shot WB under a different illuminant, saved style edited/deleted after capture, dirty Primary and out-of-order Last. Test metadata-only, None, per-shot override, never/except-cards/always, explicit XMP, unrelated XMP namespaces and output metadata stripping. Source hashes stay unchanged. |
| Viewing + overlays | A slow older preview cannot steal the latest frame; zoom/Compare/pause keep selection; jump and pin update only the intended pane. Verify pixel positions on portrait, mirrored EXIF, HiDPI, letterboxed and cropped images. With known synthetic RGB steps/edges verify clipping thresholds, histogram bins, peaking and Focus Mask. A transparent overlay preserves its hole after scale/pan/Follow Crop. Malformed, external-resource and oversized SVGs fail cleanly. Toggling layers never changes export pixels. |
| Transport + load | Run a 60 s synthetic 20 fps feed with simultaneous arrival bursts and a deliberately slow decoder. No more than one outstanding frame request/decode; p95 frame age target <200 ms on the nominal test machine; still transfers all accounted for. Measure trigger→quick and trigger→settled p50/p95, frame drops, peak RAM, actual files/s and MB/s. Keep native throughput and latency figures labeled by hardware, firmware, OS, format and cable. |
| Faults and UI | Yank cable during half-press, live long-poll, PC-only transfer and after uncertain shutter dispatch; reconnect same/different body; replace destination volume, fill disk, deny driver access and open another folder. No stuck AF, duplicate shutter, overwritten file or stale mutation. Existing palette, custom shortcuts, filters, browser/server and non-tether copy/export remain usable. |
| Hardware sign-off | On each supported OS run each Sony body with reported firmware, AF lens and MF/locked lens. Record actual provider/version/USB driver, all property access/choices in P/A/S/M and Auto ISO, physical shutter, writable card/absent card, PC Only vs PC+Camera, RAW-only and split RAW+JPEG delivery, actual preview fps, reconnect and focus steps. Mark each control supported, read-only, unavailable or unverified. Only advertise verified combinations. |

Validate native work with the repository’s Node tests, relevant workspace/Develop/preview smokes, offline notices and supported-platform Rust format, locked tests and build. For installer changes, run the packaging build on each released platform. This document specifies behavior from public documentation and PhotoCull source. It contains no measured camera session or verified PhotoCull hardware compatibility claim.
