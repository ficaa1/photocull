# Sony α7C II Wi-Fi tethering on macOS

**Implementation decision.** Give PhotoCull’s existing `SonySession<T: PtpTransport>` a second transport. The Mac initiates two PTP/IP connections to the α7C II. When the camera requires Access Authentication, carry both through one verified SSH connection to TCP 22, forwarding to the literal camera-side destination **`localhost:15740`**. Plain TCP 15740 works in the camera’s supported unauthenticated configuration. Keep Sony negotiation, shutter control, capture ordering and file staging in their current owners. The transport and its Linux tests can use stable Rust `std` with zero new Cargo dependencies. macOS supplies OpenSSH. ## Discovery and identity

Sony specifies UPnP discovery. The verified 2.01 path is to receive unsolicited IPv4 **SSDP NOTIFY** on **239.255.255.250 UDP 1900**, then fetch the description. The camera emitted notifications on both networks. Observed notification types include `upnp:rootdevice`, `urn:schemas-upnp-org:device:Basic:1` and **`urn:schemas-sony-com:service:DigitalImaging:1`**. Match the Sony service directly, or validate the service list behind a Basic/root advertisement. In a NOTIFY, the target header is **NT**. **ST** belongs to M-SEARCH and its unicast HTTP/1.1 200 response. The USN for the service has form `uuid:<UDN suffix>::urn:schemas-sony-com:service:DigitalImaging:1`. Accept case-insensitive HTTP header names. Track NTS, USN, LOCATION, sender address and CACHE-CONTROL max-age. A byebye or expiry retires a discovery candidate. Neither proves a live PTP session was lost. [Sony PTP 3, pp. 21–24][sony3] · [SSDP observations][bench] · [UPnP Device Architecture, discovery][uda]

**Active discovery is supplemental.** A standards-based test datagram is shown below. Encode each line ending as CRLF and terminate with a second CRLF. Send from an ephemeral UDP port to the multicast group and listen for unicast replies on that socket. The bench tried the DigitalImaging target and `ssdp:all`. Its multicast sends did not leave the iPhone and its unicast M-SEARCH got no reply. A positive multicast search response to any specific ST on 2.01 was not demonstrated. `urn:schemas-upnp-org:device:Basic:1` is a valid device target, but its observed NT is not evidence of a search response. The fixture advertises DigitalImaging. `urn:schemas-sony-com:service:ScalarWebAPI:1` is not the service to require. The same runs found no **`_ptp._tcp.local.`** service in five-second Bonjour browses on either network. This supports shipping SSDP and direct IP without a Bonjour dependency. [Probe source][search] · [2.01 findings][bench] · [UPnP specification][uda]

**Two HTTP documents.** A real `LOCATION` was `http://192.168.122.1:64321/dd.xml`. The infrastructure capture also used port 64321. Sony’s reference shows a different example using port 80. Fetch the advertised HTTP port and path. Use the camera IP from the validated sender/LOCATION, not the HTTP port as the PTP port. The source address and both description URLs should identify the same selected peer. Bound response size, time and redirects. A small bounded HTTP reader and a UTF-8 XML reader for these paths can use `std` alone. Handle namespaces, entities used in text such as `&amp;`, Content-Length/chunked framing and relative service URLs. Reject DTDs, external entities, cross-host links and ambiguous duplicate identity/transport fields. Treat missing discovery metadata as a reason to offer manual setup. **Rust on macOS.** Start one bounded discovery window per user action, for example five seconds. Bind a `UdpSocket` to `0.0.0.0:1900`, call `join_multicast_v4` with the group and a local IPv4 interface address (unspecified selects the default), then `recv_from` with the remaining deadline. Coalesce repeated notifications by UDN and endpoint. On a multihomed Mac allow the camera-facing interface address to be selected. Stable `std::net` does not enumerate interfaces or give a portable pre-bind reuse option for a shared SSDP socket. If UDP 1900 is occupied, permissions are missing, or the selected route misses the Wi-Fi LAN, retain manual entry. Five seconds with no NOTIFY is an empty result. Announcement frequency is unmeasured. [Rust UDP API][udp] · [Apple interface guidance][apple] · [bench][bench]

**Add by IP** must work independently of multicast and HTTP descriptions. Parse a numeric unicast camera IP, offer authentication mode if discovery cannot determine it, and perform the same selected transport handshake and model check. A typed address cannot make a sleeping, unreachable, unpaired or authentication-required camera accept plaintext. Remember the last **successful** IP plus responder identity and route/auth choice in local settings, with a per-shoot selection if present. Revalidate identity after DHCP changes or sleep. Never treat an old IP or editable discovery name as proof of the same camera.

## Access Authentication and macOS

**Authenticated infrastructure.** MENU → Network → Network Option → Access Authen. Settings → Access Authen. → On. **Access Authen. Info** under Network Option displays username, password, MAC address and fingerprint. These are separate from the Wi-Fi network credentials. Sony specifies SSH on **TCP 22**, cipher **aes128-ctr**, no remote command, and local SSH port forwarding to camera-side **`localhost:15740`**. Open two TCP streams through the forward. Firmware 2.00 reported `SSH-2.0-OpenSSH_7.9` and an ECDSA NIST P-256 host key. The hardware test explicitly reproduced rejection of the string `127.0.0.1:15740` as the *remote* destination, and success with `localhost:15740`. The local bind address may be numeric. This is SSH service forwarding, with no TLS ClientHello on 15740. Host-key type and server banner came from one body. [Sony connection reference, p. 24][sony3] · [2.00 authenticated camera test][rawbench] · [authentication info][authinfo]

A bench command using macOS OpenSSH is below. Substitute the username shown by the camera and its actual address. The example Mac port 25740 is arbitrary. Compare the displayed SHA-256 host-key fingerprint with the camera before accepting the key and entering the access password. Then connect both PTP/IP channels to `127.0.0.1:25740`. An SSH connection with no PTP/IP Init exchange has not yet opened a camera session. [Sony OpenSSH example][sony3] · [OpenSSH manual][ssh]

```sh
/usr/bin/ssh -F /dev/null -N -T -p 22 -c aes128-ctr \
  -o ExitOnForwardFailure=yes -o StrictHostKeyChecking=ask \
  -L 127.0.0.1:25740:localhost:15740 CAMERA_USER@CAMERA_IP
```

For a packaged client, keep SSH ownership in the native shell. Spawn `/usr/bin/ssh` with separate arguments, a numeric destination, validated camera user and an explicitly loopback-bound forward. Use an app-private known-hosts file and a per-camera alias. On enrollment, present the actual host key’s SHA-256 fingerprint for camera-display comparison, then pin the confirmed key. Require strict checking on reconnect, including after an IP change. Use OpenSSH’s password/keyboard-interactive prompt via a native SSH_ASKPASS helper with one-shot private IPC, or an interactive terminal for the manual workflow. SSH does not read a login password from ordinary piped stdin. Keep the password out of arguments, environment, logs, shoot files and renderer persistence. An unattended session needs an explicitly saved credential in the system Keychain. A changed key requires fresh confirmation. Confirm the child owns its listener, retry a local bind collision with a fresh port, bound startup, and terminate and reap the child after both streams close or either setup step fails. `ExitOnForwardFailure` detects local forward setup failures. The remote destination is checked only as each forwarded stream opens. A TCP loopback listener is local to the Mac and accessible to other local processes during its lifetime. [OpenSSH manual][ssh] · [SSH configuration][sshcfg] · [Sony authentication instructions][auth]

**Plaintext and pairing.** The same menu permits **Access Authen. → Off**, documented before 2.00 and exercised on 2.01. On the 2.01 infrastructure run, 15740 refused before the operator switched Off to enable Pairing, then accepted connections. No reverse-toggle experiment was recorded. The first Init Command Ack took **40.2 s**, the next about **6 ms**. For first infrastructure pairing, put the camera on PC Remote Function → Pairing, send an Init Command Request with PhotoCull’s friendly name and stable GUID, and let the operator approve on the body. Sony says it remembers up to 20 entries. Reuse the GUID on subsequent connections. On the tested camera-hosted Direct network a new GUID also connected without a prompt. The Direct run does not establish the Access Authen. toggle state for every Direct-mode combination. Use the service flags and the mode-specific setup. [Archived guide][early] · [Sony pairing sequence, pp. 24–25][sony3] · [2.01 comparison][bench]

Treat the HTTP capability flags as routing hints. If a camera previously used SSH, retain that requirement when a later unauthenticated advertisement claims SSH is disabled. Require an explicit plaintext choice for a new camera reporting Off. A user choosing plaintext saves an SSH login and exchanges the PTP/IP stream in clear on the LAN. WPA2/WPA3 protects the wireless link, while SSH also authenticates the camera and encrypts the end-to-end camera traffic. First pairing is useful for remembering a host but supplies no transport encryption. Never retry an authentication failure with a silent switch to Off. Sony specifically recommends On. [Sony access settings][auth] · [camera setup][menu]

**macOS 15 Sequoia and later.** Add this entry to the main app’s existing Info.plist, alongside its camera purpose string. The proposed SSDP and IP routes require no Bonjour declaration and macOS requires no `com.apple.developer.networking.multicast` entitlement. If a future qualified device uses Bonjour browsing, add an `NSBonjourServices` array with the actual service type, for example `_ptp._tcp` for a verified PTP service. The plist declaration explains the request. The user grants access in **System Settings → Privacy & Security → Local Network → PhotoCull**. The existing shell has no App Sandbox entitlement. [Apple TN3179][apple] · [current plist][plist] · [shell entitlements][ent]

```xml
<key>NSLocalNetworkUsageDescription</key>
<string>PhotoCull finds cameras on your local network and downloads the photos you take.</string>
```

Local outgoing TCP, including TCP 22 and the description fetch, and sending or receiving UDP multicast are subject to the privilege even through Rust/BSD sockets. The first operation can fail while the prompt is still visible. With denial, connections can fail or time out and discovery can appear empty. A bound UDP socket or a successful send does not prove receipt. Apple defines no unique denial errno for these APIs. Preserve the OS error and distinguish ECONNREFUSED, timeout, missing announcements and explicit permission errors. Offer a settings hint and retry on user action. Revocation can close an established connection. macOS tracks the responsible app when it spawns a helper. Test a Finder-launched signed bundle: commands launched from Terminal or over SSH have different privacy treatment. An Apple-issued signing identity stabilizes permission tracking across builds. [Apple TN3179, local network operations and macOS considerations][apple]

## PTP/IP 1.0 wire format

The Mac is the initiator **I** and the camera the responder **R**. **C** is the command/data TCP stream and **E** the event TCP stream. All offsets below are decimal bytes from the start of the packet. Every packet has `u32le length @0`, **including** the header, and `u32le packet_type @4`. All integer fields are packed little-endian, including unaligned u32 fields at offsets 10, 14 or 18. A GUID is an opaque array of 16 octets. Record and transmit those bytes in order. Each TCP stream has its own framing state. A read can contain half a header or multiple complete packets. Sony datasets begin at their first payload byte, without a USB container. [CIPA §§2.2–2.3, 3][cipa] · [Wireshark dissector][wire]

Let **n** be the number of 16-bit UTF-16LE name code units **including** the final zero, 1–40. An empty name is two zero bytes. Names have no count prefix. Let **p** be the number of u32 parameters actually carried, with no count, padding or unused slots on the wire. **b** is the number of payload octets in one data packet. [CIPA §2.3][cipa]

| Type (hex u32) | Socket and direction | Fields after the header | Total length in bytes |
|---|---|---|---|
| 01 Init Command Request | C I→R | initiator GUID @8..23, name @24, protocol version u32 @24+2n | 28+2n |
| 02 Init Command Ack | C R→I | connection number u32 @8, responder GUID @12..27, name @28, version u32 @28+2n | 32+2n |
| 03 Init Event Request | E I→R | connection number u32 @8 copied verbatim from type 02 | 12 |
| 04 Init Event Ack | E R→I | empty | 8 |
| 05 Init Fail | C or E R→I during init | reason u32 @8: 1 rejected initiator, 2 busy, 3 unspecified | 12 |
| 06 Operation Request (Cmd Request) | C I→R | data-phase info u32 @8, opcode u16 @12, transaction ID u32 @14, parameters @18+4i | 18+4p, p=0..5 |
| 07 Operation Response (Cmd Response) | C R→I | response code u16 @8, transaction ID u32 @10, parameters @14+4i | 14+4p, p=0..5 |
| 08 Event | E R→I | event code u16 @8, transaction ID u32 @10, parameters @14+4i | 14+4p, p=0..3 |
| 09 Start Data | C in direction of data flow | transaction ID u32 @8, total dataset length u64 @12 | 20 |
| 0A Data | C in direction of data flow | transaction ID u32 @8, bytes @12 | 12+b |
| 0B Cancel | I→R on **both C and E** for initiator cancellation | transaction ID u32 @8 | 12 |
| 0C End Data | C in direction of data flow | transaction ID u32 @8, final bytes @12, possibly empty | 12+b |
| 0D Probe Request | E either direction | empty | 8 |
| 0E Probe Response | E opposite direction to request | empty | 8 |

Initialize version **0x00010000**, bytes `00 00 01 00`. Validate name bounds, terminator, exact remaining version field and compatible major version. Type 0 is invalid and 0x0F and above are reserved in 1.0. Check all lengths by type before reading variable fields or allocating. Use `from_le_bytes` on checked slices. [CIPA §§2.3, 3 and Annex 5.5][cipa]

**Connection order and transaction IDs.**

1. Dial C at the selected endpoint. Send 01, receive 02. Only then dial E to the **same endpoint**. Send 03 with the returned connection number, receive 04. On 05 or failure opening E, close both. The number associates these two sockets and can be reused by the responder. It is distinct from SessionID, transaction ID and both GUIDs. A stable locally generated initiator GUID supports pairing. For a std-only Mac implementation, read 16 bytes from the OS random device, set UUID v4 version/variant bits, and persist once per installation using exclusive/atomic local settings creation. [CIPA §2.2.3][cipa] · [Sony pairing][sony3]
2. With both channels ready and the event reader active, **`PtpIpTransport::open()` sends `OpenSession 0x1002`, TID 0, parameter [1]** (nonzero SessionID selected by PhotoCull), phase 1. Wait for `0x2001 OK` before declaring open. If an implementation queries `GetDeviceInfo 0x1001` *before* OpenSession, its pre-session TID is also 0. In this repository `SonySession::connect()` calls `transport.open()` first, so its GetDeviceInfo uses **TID 1**. Do not add a second GetDeviceInfo in the IP adapter. Advance once per subsequent request, including each new busy retry. Reserve 0 and 0xFFFFFFFF. End/reopen a session before exhausting the usable sequence. Never assume ownership of someone else’s already-open session on `0x201E`. [CIPA §§1.6.5, 2.3.6][cipa] · [Sony connect sequence][sony3] · [bench client open/close][client] · [PhotoCull connect][session]
3. On orderly shutdown, let `SonySession::close()` release held camera controls. Then **`PtpIpTransport::close()` sends `CloseSession 0x1003`** with the next in-session TID, no parameters, phase 1. Consume its response before shutting down E and C. On broken framing, a lost socket or an expired deadline, tear down both immediately. A failed or partial open must unwind too. ICC continues to own its USB open/close. [CIPA §§1.6, 2.2.3.3][cipa] · [bench close][client] · [session][session]

These hex vectors include their entire PTP/IP headers. The third is a published 2.01 event. Its TID is the asynchronous sentinel, so it must not be matched against the current command. [2.01 event fixture][objectevent]

```text
OpenSession(1), TID 0     16 00 00 00 06 00 00 00 01 00 00 00 02 10 00 00 00 00 01 00 00 00
OK, TID 0                 0e 00 00 00 07 00 00 00 01 20 00 00 00 00
Sony ObjectAdded          12 00 00 00 08 00 00 00 01 c2 ff ff ff ff 01 c0 ff ff
```

**Data direction and completion.** Encode `DataPhase::None` and `In` as **1**, `Out` as **2**. CIPA reserves 0 for an exceptional vendor request whose data direction the initiator genuinely cannot determine. A PhotoCull operation always supplies its direction. Both shutter-bridge and the 2.00 camera client use 1 for reads, and the latter emits 2 for writes. [CIPA §2.3.6][cipa] · [bench encoder][kit] · [2.00 tether client][rawclient]

| Data phase | Successful command-stream exchange after 06 |
|---|---|
| None | R→I 07. |
| In | R→I 09, zero or more 0A, exactly one 0C, then 07. Concatenate only bytes beginning at offset 12 of 0A and 0C. |
| Out | I→R 09, zero or more 0A, exactly one 0C. R→I 07. For `Out(&[])`, send 09 with total 0 and an empty 12-byte 0C. |

A small dataset can fit entirely in **End Data following Start Data**. A large dataset can use any number of Data packets followed by a populated or empty End Data. An empty dataset can have Start(0) and End(empty). CIPA also allows the responder to reply immediately to a phase-1 operation. Preserve a complete, error-code response with no data or one interrupting a data phase as a failed operation, including its TID and parameters. A data-in command that returns OK with no data may have operation-specific meaning (Sony explicitly retries an empty 0x9202 dataset). A successful response *after a started but unterminated phase* is malformed. A bare End with no Start has no support in the standard sequence or in the cited camera evidence. The 2.01 repository publishes file hashes and datasets, not the complete sequence of Data/End headers for its ARW transfers. Neither a specific chunk size nor a compulsory empty End for this firmware is established. [CIPA §§2.3, 2.7][cipa] · [bench fixture inventory][fixtures] · [Sony capabilities retry][sony3]

`total_data_length == 0xFFFF_FFFF_FFFF_FFFF` means unknown. For any other value, the sum of the payloads on a successful transfer must equal it exactly. Each packet’s u32 wire length remains mandatory even for an unknown aggregate length. A mismatch between **PTP/IP Start Data** and the received total is a framing/transfer failure. A discrepancy with the earlier Sony **ObjectInfo.ObjectCompressedSize** is separately owned by `drain_one`, which already handles short and under-reported objects. Preserve that distinction on disk. [CIPA §§2.3.9–11][cipa] · [PhotoCull capture drain][session]

**Cancel and liveness.** Under CIPA §2.7 an initiator cancelling an in-flight transaction sends type 0B with the same TID on **both** streams at packet boundaries. A responder can terminate using an Operation Response such as `Transaction_Cancelled 0x201F`. The current transport trait has no asynchronous cancel callback. PhotoCull can retire both connections if a deadline or sink failure makes completing/draining the current transaction unsafe. Sending a PTP cancel does not undo an exposure. [CIPA §§2.2.3.3, 2.7][cipa] · [transport contract][trait]

Answer each event-channel Probe Request immediately with 0E. CIPA recommends **10 seconds to wait for a reply** to an issued probe. It recommends sparing use during a long transaction and specifies **no repeating idle-probe interval**. It separately recommends TCP keepalive and disabling Nagle. shutter-bridge’s client used TCP keepalive and later an application-level GetDeviceInfo at approximately 10-second intervals. It observed six successful heartbeats on 2.01. An iOS suspension disconnected even with recent activity. Its cited 30-second idle cutoff came from another model. A macOS α7C II timeout and mandatory periodic E-channel ping have not been measured. Keep the E reader responsive during long RAW reads and use the existing actor’s idle property polling first. Measure idle survival before adding any extra periodic command. Stable Rust’s TCP keepalive setter is experimental on the inspected toolchain. `set_nodelay(true)`, bounded I/O and PTP probe replies are available in stable `std`. [CIPA §§2.2.3.2, 2.3.13–14][cipa] · [2.01 results][bench] · [spike socket options][client] · [Rust TCP API][tcp]

A fresh Sony C201 [FFFFC001] also wakes the capture drain. 2.01 sent this event on both Wi-Fi topologies after a physical shutter press, about 0.4 s after one Direct capture. GetObjectInfo then GetObject on **0xFFFFC001** is Sony’s captured-file sequence. The 2.01 bench explicitly left fetching this pseudo-handle untested. Its successful GetObject on **card** handles in Contents Transfer mode is separate evidence. Keep 0x9210/0x9212 whole-card import out of the tether open path. [Sony acquisition sequence, pp. 29–32, 65–66][sony3] · [2.01 shutter evidence][bench] · [USB queue interpretation][usb] |
| `0xFFFFC002 Live View` | Sony specifies D221 enabled, one GetObjectInfo on FFFFC002, then repeated GetObject on FFFFC002. Use the existing Sony live-view dataset/JPEG decoder. There is actual **wireless** evidence on 2.00 for a different route: an HTTP JPEG stream forwarded to `localhost:60152`; Sony also illustrates a liveviewstream URL in its discovery example. That capture does not validate GetObject(FFFFC002) on 2.01. Exercise the pseudo-handle over Wi-Fi before enabling it for this profile. Surface Live View unavailable if it fails while capture works. Any later HTTP implementation needs separate qualification and, in authenticated mode, a separate forward. [Sony Live View, pp. 31, 65–67][sony3] · [authenticated Live View test][rawbench] · [existing session][session] |

## Rust adapter, native commands and Camera panel

**Transport boundary.** Add `protocol/ptpip.rs` and export it from the std-only protocol module. Construct `PtpIpTransport` from the selected socket endpoint, a persisted 16-byte initiator GUID and a bounded friendly name. For SSH, the endpoint is the verified forward with a separately owned tunnel guard. Discovery, HTTP descriptions, SSH UI and settings live above the packet transport. Keep one actor as the sole writer of C. The transport owns both streams, E-reader shutdown handle, queue, generation, next TID, open/lost state and the peer GUID from 02. [Current transport][trait] · [protocol entry point][protocol] · [native actor][actor]

| Entry point | Required behavior |
|---|---|
| `open(deadline)` | Use `TcpStream::connect_timeout` with the remaining budget for each socket, `set_nodelay(true)` on both, handshake in order and start the E reader before OpenSession. Use one fresh generation per open/reopen. Shut down and join the previous reader first. CIPA suggests 30 s for establishment. PhotoCull currently passes only its 10 s command timeout and a real first pairing took 40.2 s. Give the session a separate **open timeout** (proposed 60 s for Wi-Fi, existing timing for USB), including reopened negotiation trials. Retain the existing 10 s normal command and 120 s object-transfer budgets initially. Complete any human SSH enrollment before this transport budget begins. Respect the caller’s absolute deadline. |
| `transact(request, phase, deadline)` | Validate parameter count before sending anything. Encode an 18–38 byte request and assign the next TID once. Serialize commands. For data-out, write Start, bounded chunks and End. For data-in, read exactly the next header, validate type/length/TID, then stream each payload through a fixed scratch buffer (e.g. 64 KiB) straight to `DataPhase::In { sink, limit }`. Check known totals against limit at Start. For each packet check `payload_len <= limit - bytes_in` and the known remaining length before writing. Use checked u64 accounting, even on 32-bit hosts. Never allocate a Vec sized by a packet, transfer or ARW. A small bounded metadata Vec belongs to the caller. Return `Reply { code, params, bytes_in }` at the matching response. A partially written object stays staged until the existing owner validates completion. |
| Absolute I/O deadlines | Set read/write timeouts from `deadline.checked_duration_since(Instant::now())` before **each partial** socket read/write. Stop on expiry before passing zero to the setters. A single timeout around `read_exact` or `write_all` can be extended indefinitely by trickled bytes. Maintain header/payload offsets across short reads, retry Interrupted within budget, and map timeout/WouldBlock consistently. A zero-byte read means EOF. Check time between file writes too. A synchronous caller-supplied `Write` can itself block in the OS beyond a network deadline. Document that limitation. Never start another transaction on a partially framed stream. |
| `poll_event()`, `wait_event(until)` | E thread consumes bounded control frames, validates Event and enqueues `Ptp { generation, code, params }`. Decode the event TID but do not filter on current command TID. Only that reader writes E probe replies, or serialize E writes if later adding cancel. Use a bounded queue with a condition variable, coalesce property dirties, preserve ordering for object events, reserve a terminal notification even when full. On overflow that loses ordering, force resynchronization/loss. Wake blocked callers. Idle silence on E is normal. A partial E frame needs a finite completion deadline. |
| Failure and `close(deadline)` | Either socket breaking invalidates the pair. Atomically retire the generation once, `shutdown(Both)` on both sockets so a C read or E thread unblocks, and enqueue exactly one terminal event. Use `SessionLost` for network EOF/reset, malformed or abandoned transactions and tunnel death. Reserve `Removed` for positively known device removal, never simple SSDP silence. Map local socket permission failures, busy init, sink failure, size violation and timeouts to the existing typed errors. Preserve the first cause for the caller. Suppress deliberate-shutdown EOF events. Normal close sends 1003 only on a known clean open session. Always release both streams, join the reader, reap the tunnel and clear state. Drop provides abortive cleanup on partial construction. |

If the sink refuses a chunk, keep the original sink error and mark this generation unusable. An interrupted capture-object read can already have consumed the camera queue head. A retry by handle can fetch the *next* shot. Do not publish a partial file, replay a shutter edge or resume an indeterminate `GetObject(FFFFC001)`. Reconnect through a new verified session and let the shoot journal reconcile outstanding work. The IP adapter has no complete retained RAW or late ICC callback to offer for disk recovery. [Session drain and shutter ownership][session] · [native transfer handling][actor] · [staging][stage]

**Native integration.** Today `Actor.session` and `ready_session` name `SonySession<IccTransport>`, `connect` constructs ICC directly, `service` consumes ICC orphans and `reconnect_target` searches ICC devices. Use an actor-side enum `CameraTransport::{Usb(IccTransport), Wifi(PtpIpTransport)}` forwarding the existing trait methods, including event wait and generation. Store `SonySession<CameraTransport>` once. Dispatch ICC `take_orphan`, late claims and retained payload recovery only for the USB variant. On Wi-Fi use the normal stage writer, progress, journal and capture queue. Make reconnect select the previous transport and verify responder GUID/model, serial when available, and pinned SSH identity before resuming. Scope generation keys by transport or use a common allocator to avoid collisions with outstanding ICC claims. [Actor and reconnection][actor] · [ICC adapter][icc] · [session][session]

|---|---|

## Physical-camera acceptance

Use a disposable test shoot, a synthetic photographic subject and **Dest.+Camera** with a writable card. Record camera Setup → Setup Option → Version, topology, auth setting, Mac build and app signature with each result. Keep credentials, host IDs, serials and image payloads out of published traces. For authenticated runs, collect the inner PTP/IP headers on the local forward or from a header-only adapter trace. A capture on Wi-Fi alone sees SSH ciphertext.

1. On a 1.x body if available, then on 2.00 and 2.01, exercise Direct and infrastructure. Record actual menu labels, direct address, first connection and reconnect, including a Mac-hosted AP if that topology will be advertised. Save redacted SSDP headers and both descriptions. Record sent multicast ST, received ST or NT, source, LOCATION and listening time. Browse `_ptp._tcp` separately if testing a Bonjour claim. Count only an actual unicast search reply as a successful M-SEARCH.
2. For infrastructure On, verify host fingerprint against the body, authenticate, open both forwarded channels and run OpenSession through CloseSession. Check correct handling of a changed key, cancellation and wrong password. For Off, select Pairing and observe first approval, subsequent reconnect with the same GUID and a fresh GUID. Time each TCP connect, Init Ack and OpenSession separately.
3. Exercise physical shutter, software shutter, RAW-only and RAW+JPEG with the existing engine. Log 9202 and 9209 parameter lists and response codes, D215 before/after the shot, C201, 1008 and **1009 on FFFFC001**. Record each C frame’s type, length and TID, Start total, Data count and End payload size. Compare completed host bytes against the same original on card. Test **1008/1009 on FFFFC002** and JPEG decode separately from HTTP Live View. These measurements are needed for PhotoCull’s Wi-Fi capability claims.
4. With the Mac awake and camera power-saving settings recorded, time foreground idle sessions with no commands, normal property polling and optional probes separately. Record which peer sent the first probe or closed which stream. Repeat during a long download and across Mac sleep/wake. No published test fixes one α7C II event-probe cadence. On macOS 15+ test allow, deny, retry and revoke from the signed GUI, plus interrupted transfer, disk-full handling, and a DHCP reassignment to a different body. Re-run the existing USB tether smoke after adding transport dispatch.
